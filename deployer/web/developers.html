用 MailEdge 开发

MailEdge 是完整跑在 Cloudflare 上的邮箱系统，也是一组可编程的 HTTP 接口。开发者可以调用它发信、查信、管渠道，或扩展新的发信服务商。

目录 一、HTTP API 　发信 　查询与统计 　渠道管理 　分享与下载 二、扩展发信渠道（Provider SDK） 三、本地开发

HTTP API

除健康检查与初始化外，全部接口需要登录会话（浏览器用 Cookie，脚本先调登录接口拿会话）。

基础地址：https://你的-mailedge-域名

发信

POST /api/mail/send —— 支持 JSON 或 multipart 两种提交。

JSON 方式（附件用 base64 内联，脚本调用方便）：

curl -X POST https://your-domain/api/mail/send \
  -H 'Content-Type: application/json' \
  -b cookie.txt \
  -d '{
    "from": "you@yourdomain.com",
    "to": "someone@example.com",
    "cc": ["cc@example.com"],
    "bcc": ["hidden@example.com"],
    "subject": "你好",
    "text": "纯文本正文",
    "html": "<p>富文本正文</p>"
  }'

multipart 方式（前端上传用，payload 字段是 JSON，文件放 attachments）：

curl -X POST https://your-domain/api/mail/send -b cookie.txt \
  -F 'payload={"from":"you@yourdomain.com","subject":"报价单","text":"见附件"}' \
  -F 'attachments=@quote.pdf'

Markdown 快捷方式（服务端自动转邮件安全 HTML，原文作纯文本版）：

curl -X POST https://your-domain/api/mail/send -b cookie.txt \
  -H 'Content-Type: application/json' \
  -d '{"from":"you@yourdomain.com","to":"a@b.com","subject":"周报","markdown":"## 本周\n- 完成 A\n- 完成 B"}'

响应里的 smartAttachments 会说明哪些附件真发了、哪些因超过 3MB 自动转成了 R2 下载链接；internalId 是跨渠道不变的邮件 ID，用于去重与追踪。

发件地址必须是当前账户持有的信箱；正文为空会被拒绝。附件超过 SMART_ATTACHMENT_THRESHOLD（默认 3MB）自动转下载链接。

查询与统计

方法路径说明
GET/api/messages邮件列表，支持 folder q before limit 分页
GET/api/messages/:id邮件详情（拉取后自动标记已读）
PATCH/api/messages/:id已读 / 星标 / 移动文件夹
DELETE/api/messages/:id删除（先进回收站，回收站再删才彻底清除）
GET/api/messages/:id/attachments/:aid收件附件下载
GET/api/stats各文件夹未读数
GET/api/mail/outbox发信记录（状态机视图）
POST/api/mail/outbox/:id/retry手动重试（沿用同一 internalId，不会重复生成新邮件）

聚合视图：传 mailboxId=all 可一次查询所有信箱，返回条目带 mailboxId 与 mailboxAddress 用于区分来源。

curl -s "https://your-domain/api/messages?mailboxId=all&folder=inbox&limit=20" -b cookie.txt

渠道管理

方法路径说明
GET/POST/DELETE/api/providers发信渠道增删查（管理员），密钥接口只返回脱敏值
POST/api/providers/:id/default设为默认渠道
POST/api/providers/:id/test测试发送
GET/api/auth/me当前用户与信箱

分享与下载

方法路径说明
GET/POST/api/shares列出 / 创建附件分享链接
POST/api/shares/:token/revoke撤销分享
GET/d/:token大附件公开下载（Worker 校验 token / 有效期 / 撤销状态后从 R2 出流）

扩展发信渠道（Provider SDK）

MailEdge 把"发信"抽象成一个接口。新增一家服务商（SES / Mailgun / Postmark / 任意 SMTP），只需要三处改动，不改任何上层逻辑。

核心接口

// src/mail/types.ts
export type MailProviderType = "cloudflare" | "resend" | "sendflare" | "smtp";

export interface MailProvider {
  readonly type: MailProviderType;
  send(input: SendMailInput): Promise<SendMailResult>;
}

export type FailureKind = "transient" | "permanent";
// transient（网络故障/429/5xx）才允许切换备用渠道重试；
// permanent（域名未验证/地址非法/内容被拒）立即失败，绝不重发

三步新增一家服务商

  1. 在 src/mail/providers/ 加一个类，实现 MailProvider
  2. 在 src/mail/types.ts 的 MailProviderType / MailProviderConfig 加新类型
  3. 在 src/mail/factory.ts 加一个分支
// src/mail/providers/mailgun.ts（骨架）
export class MailgunMailProvider implements MailProvider {
  readonly type = "mailgun" as const;

  constructor(private readonly apiKey: string, private readonly domain: string) {}

  async send(input: SendMailInput): Promise<SendMailResult> {
    // 调用 Mailgun REST API，失败时返回 { success:false, failureKind }
    return { provider: this.type, success: true };
  }
}
// src/mail/factory.ts（加一个 case）
case "mailgun":
  return new MailgunMailProvider(config.apiKey, config.domain);
default: {
  const exhaustive: never = config;
  throw new Error(`不支持的邮件服务`);
}
分类规则很关键：permanent 错误会被立即置为 failed，不会换渠道重发——否则一封被拒的邮件会在三个平台各发一次。分类实现见 src/mail/errors.ts。

本地开发

npm install
cp .dev.vars.example .dev.vars          # 填入两个 openssl rand -base64 32
npx wrangler d1 migrations apply mailedge --local
npm run dev                            # http://127.0.0.1:8787

改前端时另开一个终端跑 npm run dev:web 做增量构建。测试与检查一条命令：

npm run verify   # lint + 三套 typecheck + 全部测试（跑在真实 workerd 里）

测试不是 Node 模拟，而是真实 workerd：crypto.subtle、D1、Durable Object、cloudflare:sockets 的行为与线上一致。

本地模拟收信：curl -X POST 'http://127.0.0.1:8787/cdn-cgi/handler/email?from=a@x.com&to=you@domain.com' --data-binary @test.eml -H 'Content-Type: message/rfc822'
