使用说明

从一键部署到收信、发信、更新、绑定域名、卸载，一步步讲清楚。

一、部署

部署只需三个前提：一个 Cloudflare 账户、一个用于收信的域名（托管在 Cloudflare）、以及一个部署用的 API Token。

  1. 打开 一键部署 页面
  2. 创建 Cloudflare API Token：选 Edit Cloudflare Workers 模板，再加 D1 → Edit 一项权限
  3. 粘贴 Token → 验证（权限体检全绿）→ 选择账户 → 一键部署
  4. 部署完成后会得到管理面板地址（xxx.workers.dev）
部署是幂等的：重复部署会复用已有数据库与配置，只更新代码。重新部署即「更新到最新版」。

二、初始化

  1. 打开管理面板地址，进入初始化页
  2. 创建管理员账号（邮箱 + 密码）
  3. 添加第一个收件地址（如 support@你的域名）

三、收信

要让域名下的来信进入 MailEdge，需要两个层面的配合：

  • MailEdge 侧：设置 → 收件地址 → 添加你的邮箱地址（可添加多个）
  • Cloudflare 侧：Email Service → Email Routing → 把域名收到的信投递给 mailedge Worker（Catch-all 或精确地址）

兜底信箱（catch-all）：设置为兜底的地址会接收域名下所有未单独登记的来信，防止漏信。

收件地址必须与 Email Routing 规则一致，否则会退信（550 未知收件人）。

四、发信

发信渠道共四种，可在设置 → 发信服务配置，支持主备自动切换：

渠道配置要点
Cloudflare Email Service无需配置，点「一键连接」即可；发往外部邮箱需 Workers Paid
ResendAPI Key + 在 Resend 后台验证发件域名
SendflareToken（+ 可选 Secret / API 地址）
SMTP主机 / 端口 / 账号密码，支持 Gmail 一键预设（587 STARTTLS）

用收件地址回复：回复邮件时，发件人自动使用「收到信的那个地址」，对方看到的 From 就是它。前提是该地址的域名在所用渠道验证过——Cloudflare 渠道需要在 Email Service → Email Sending 里 onboard 域名（自动配 SPF/DKIM，等 5-15 分钟生效）。

五、日常使用

  • 收件箱：多信箱聚合视图、分类（重要/更新/营销/社交/其他）、搜索、分页、星标、未读计数
  • 写信：支持 Markdown、抄送、密送、多附件；大附件自动转下载链接
  • AI 助手（可选）：自动回复、邮件总结、收信分类；可接 OpenAI、DeepSeek、Kimi、本地 Ollama 等兼容服务
  • 实时推送：新信秒级到达（WebSocket），断线自动重连 + 60 秒轮询兜底
  • 双语：界面自动跟随浏览器语言，可手动切换

六、一键更新

项目发布新版本后，在 MailEdge 里即可一键更新：

  1. 设置 → 更新 → 保存「更新 Token」（Workers Scripts 权限）与账户 ID（AES-GCM 加密存储）
  2. 点「一键更新到最新版」，自动重新部署最新代码，保留邮件数据与配置

也可以到 一键部署 页面重新部署，效果相同。

七、绑定自己的域名

默认使用 xxx.workers.dev 访问。想用自己的域名：

  1. Cloudflare 后台 → Workers 与 Pages → mailedge → 设置 → 域名 → 添加自定义域
  2. 填写域名（如 mail.你的域名.com），按提示添加 DNS 记录

八、卸载

  1. 打开 一键部署 页面底部「卸载已部署的 MailEdge」
  2. 粘贴 Token → 扫描资源（Worker / D1 / R2 / Email 规则）
  3. 勾选要删除的资源 → 确认删除
卸载会永久清空邮件与附件数据，不可恢复。
